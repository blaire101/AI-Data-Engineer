EBS 类型选择

Aurora 核心特性
  • 兼容 MySQL（5x 速度）/ PostgreSQL（3x 速度）
  • 6 份副本跨 3 AZ，2 份丢失仍可写，3 份仍可读
  • 存储自动扩展 10GB → 128TB
  • Aurora Serverless：间歇性/不可预测负载，自动暂停
  • Aurora Global Database：主 Region 写，5 个只读 Region，RPO <1s
  • Aurora Multi-Master：多写节点，高可用写入
  • RDS Proxy：连接池，Lambda 必用，避免连接耗尽
DynamoDB 核心
  • 延迟单位数毫秒（single-digit millisecond）
  • DAX内存缓存，微秒级，只给 DynamoDB 用

  • Provisioned流量可预测，手动设 RCU/WCU，可 Auto Scaling
  • Global Tables多区域多活，必须开 Streams
  • Streams捕获数据变更 → Lambda 触发
  • TTL自动删除过期 item，不消耗 WCU

VPC 连接方式
  • VPC Peering1对1，不可传递（A-B-C，A 不能通过 B 连 C）
  • Transit Gateway中心辐射，可传递，多 VPC/账号/Region 首选
  • PrivateLink服务发布给消费者，无需 VPC Peering
  • Site-to-Site VPN公网加密，分钟级搭建，便宜
  • Direct Connect物理专线，稳定低延迟，1/10 Gbps
  • DX + VPNDX 为主，VPN 作 failover，最高可用
多 VPC 互联 → Transit Gateway，不是 VPC Peering（不传递）

QUESTION 01 · 安全 Domain (30%)
公司需要确保 AWS Organizations 中所有账号都不能创建公网 S3 存储桶。不管账号管理员有多大权限，该策略都必须生效。应该使用什么？
  • A给每个账号的管理员创建一个 S3 Deny public access 的 IAM Policy
  • B在每个账号中开启 S3 Block Public Access 设置
  • C在 AWS Organizations 的根 OU 上创建一个 SCP，拒绝 s3:PutBucketPublicAccessBlock 以外的操作
  • D使用 AWS Config 规则检测公网 S3 桶并自动修复
✓ 答案：C

SCP（Service Control Policy）在 Organizations 层面生效，覆盖任何账号内的 IAM Policy，包括 root 用户（唯一例外是管理账号）。它是防止某类操作的最终防线。

A：IAM Policy 只约束特定用户，账号内其他用户或 root 不受限
B：账号管理员可以随时关闭这个设置
D：Config 是检测和修复，不能阻止操作，有时间延迟

QUESTION 07 · 弹性架构 Domain (26%)

  • A在一个 AZ 的公共子网部署一个 NAT Gateway，所有 AZ 共用
  • B给每个私有子网的 EC2 分配公网 IP
  • C在每个 AZ 的公共子网各部署一个 NAT Gateway，各 AZ 路由表指向本 AZ 的 NAT Gateway
  • D使用 VPN 连接到公司网络，再从公司网络访问互联网
✓ 答案：C

NAT Gateway 是 AZ-bound（绑定到特定 AZ）。最佳实践是每个 AZ 部署一个，各自独立，AZ 故障不影响其他 AZ 的出网。

A：共用一个 NAT Gateway = 单点故障，该 AZ 挂了所有 AZ 都断网
B：给私有子网 EC2 公网 IP 破坏了网络隔离，外部可主动连接
D：VPN 路径绕远，增加延迟和复杂度
